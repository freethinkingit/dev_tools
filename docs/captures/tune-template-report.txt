● ## Blocked

  Nothing blocked.

  ## Shipped

  - The link store, which saves a long URL under a new six-character code and looks it up again, is built in `linkshort/store.py`. Both of its tests pass: a saved URL comes back by its code, and an unknown code returns nothing (`python3 -m unittest discover -s tests`).
  - The `add` command, which prints a new code for a URL, works. Running `python3 -m linkshort --db x.db add https://example.com` printed `uai5kc`.

  ## In flight

  - **The README's serve command fails.** `python3 -m linkshort serve --db links.db` stops with `unrecognized arguments: --db x.db`, because `--db` has to come before the subcommand. Anyone who follows the README can't start the server. You can fix it by changing the README to `python3 -m linkshort --db links.db serve`, or by moving `--db` onto each subcommand so the README stays as written.
  - **The redirect server has no tests.** `serve` in `linkshort/__main__.py` answers `/<code>` with a 302 redirect, or a 404 when the code is unknown. Nothing has run it yet, so this is from reading the code only.
  - **Two links can get the same code.** `add` makes a random code and doesn't check whether it's already taken. I expect a clash would make the database reject the insert with an error, but I haven't tested this.
  - **`.ponderly/` is not committed.** It holds the new status template and is untracked on `main`.

  ## Up next

  1. Fix the README's serve command.
  2. Add tests for the redirect server and for `add` when two codes clash.
