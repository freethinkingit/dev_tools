# Implementation Plan

## Overview

The first wave lays down what needs nothing else: the five lenses, the `review-arm` agent, the `shop` eval fixture, the adapter's pure `findings.py`, and the three report and convert scripts, which read fixed file shapes. The second wave tunes the lenses with the author and writes the `review` skill over them and the arm, the adapter's entrypoint over `findings.py`, and the seeded property tests for both. The third wave writes the eval cases against the finished skill, the adapter's process tests and the Dockerfile. The fourth wires the two harness Makefiles, the leaderboard files and the documentation. The fifth and sixth are the author's own runs: the evals, one pull request and the test set through ReviewBench, then Martian, each report pasted into `docs/evidence.md`. The last wave is the leaderboard, which runs only on the Owner's yes. Every code task is proved by an ephemeral check plus `make validate`; the tests are tasks of their own; the skill and the agent are proved by their eval cases. There is no issue yet; the branch is `code-review-agent`. Python is 3.9-syntax standard library, as `checks/` and `docs/captures/render.py` are written.

## Notes

- Python is 3.9-syntax standard library throughout, as the rest of `checks/` is; scripts resolve paths from their own location and run under `python3 -I` in the image.
- Tests follow the team's tests rule: one test per path and per input, named as the behaviour it asserts; the only loops are the seeded property tests the design names.
- A skill or agent is proved by its eval cases, never by a check that greps its text.
- Arms gather the diff themselves; the skill never pastes a diff into a launch, and never writes a file inside the repository.
- Headless facts to confirm while building task 2.2 and mark in the README if they differ: that `--plugin-dir` loads the plugin's agents and hooks in `-p` mode, that `CLAUDE_CODE_EFFORT_LEVEL` and the forced sub-agent model reach the `wave-reviewer` despite its own `effort: high`, checked with `/tasks` or the session's JSON, and that the JSON result carries `total_cost_usd` and `duration_ms`.
- `rg` needs a path argument in this environment; `rg <pattern> .`.
