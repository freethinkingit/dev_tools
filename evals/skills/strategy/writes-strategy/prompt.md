/ponderly:strategy Docs platform 2028. Answers to the strategy questions: the name is "Docs platform 2028"; the horizon is January to December 2028, reviewed at the end of each quarter, and the work moves the company's product documentation from a wiki to a docs site built from the product repositories. Goals: one, every product's reference documentation is published from its repository on each release, worth ending the week of manual copying the support team does before each release; two, readers find an answer by search in under ten seconds, measured by search-to-click time, worth fewer support tickets, which are a third documentation questions today; three, documentation is versioned per release, worth letting customers on older releases read the pages that match them. Current state: about 900 wiki pages, edited by hand, no versions, a wiki search that matches titles only, and three of the twelve products already keep Markdown docs in their repositories. Principles and constraints: documentation lives beside the code it describes; the site is static and builds in under ten minutes; no new vendor, hosting stays on the company's existing cloud account; the team is two writers and two engineers. Streams of work: a docs build pipeline that turns each repository's Markdown into the site on release, Q1 to Q2, serving goals one and three; search, Q2 to Q3, serving goal two, once the pipeline publishes; the migration of the wiki pages into the repositories, Q1 to Q4, serving goal one. Risks: product teams do not keep their docs current once the docs sit in their repositories, likely and costly, met by a docs check in each repository's pull request template; the migration takes longer than a year, moderate, met by migrating the most visited pages first. Out of scope: translations, deferred to 2029; the marketing site, which another team owns; an API reference generator, since the products' existing generators are kept. I will not answer further questions in this run: decide anything else yourself and carry it to the hand-back as an open question.
